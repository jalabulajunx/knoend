# Recipes: one folder of tested layouts, agent screens as data

2026-10-18 - Sundar (Claude Code)

## What

Layouts shipped with OpenPager move from `libraries/builtin/` to `recipes/`, split by what they
cover: `apps/`, `sites/` (`<host>.toml`, `<host>/<page>.toml`) and `agents/`. Every recipe is compiled
in and validated. Two additions to the library format (`spec/schemas/library.schema.json`):

- `[[pack.tested]]`: who saw it work, on which OS, when (and the desktop or browser).
- An `agent` action (`reply` = allow, always, deny, stop, option, done, decline, go_to) for libraries
  matched by `match.agent`. Claude Code's permission, question and "Go to Claude" screens are now
  recipes (`claude-code/permission`, `/question`, `/elsewhere`); the companion fills in what changes
  per request.

The AI drafts Sundar used on Linux (15 of 18) were promoted with his `tested` entry.

## Why

- AI drafts lived only on the computer that made them, unreviewed, so working layouts never reached
  anyone else, including the other OS. A shared folder with a record of what was tested where is
  the base for a board's settings travelling between computers (#16) and for boards with roles (#15:
  a pager board uses only `agents/`).
- One file per app for every OS (per-OS `match`, `Primary` shortcuts) instead of a folder per OS:
  per-OS copies would drift. The `tested` list says which OS is proven.
- Agent screens as data: Codex or another agent becomes a recipe rather than code, Tom's
  terminal-agent keys can use the same screens, and a person can change them without a rebuild.

## Alternatives rejected

- **Folders per OS** (`linux/`, `macos/`): duplicate files for the same app, which drift apart.
- **Keeping agent screens in code**: every new agent or layout change would need a release.
- **Promoting every draft**: the three Navidrome drafts match a home server's LAN address and its
  positional selectors; they stay local until a recipe can match a self-hosted app on any host.

## Open

- Matching self-hosted web apps (Navidrome, Jellyfin, Home Assistant) by the app rather than the host.
- GitHub repository pages: the promoted ones are for this project's repository; a recipe for any
  repository needs paths relative to the current repository.
- `docs.google.com` uses `Ctrl+F5` / `Ctrl+M` as drafted on Linux; on macOS Slides uses Cmd. Needs
  per-OS keys or a macOS test.
